# Tickets on dricket — what dk v0.5.0 really does

Status: observed, 2026-11-04 (E14-1). Companion of
[`fit-analysis.md`](fit-analysis.md) and
[`dricket-requirements.md`](dricket-requirements.md). The analysis was written
without running `dk`; the E14-1 contract suite did. This page lists where the
real output differs from, or sharpens, what the analysis assumed. The raw
output is committed as fixtures:
`packages/tickets-engine/src/store/fixtures/dk-v0.5.0/` (written by
`dricket-contract.spec.ts` with `DREY_CAPTURE_DK_FIXTURES=1`).

Method: `dk` v0.5.0 built from tag `v0.5.0` (`d28181b`) of the owner's
dricket repo into a temp directory (the repo itself untouched); a scratch
store (`dk init <tmp> t`, three `dk add --unclaimed`), a temp `HOME`, a temp
`DK_DATA_DIR`, `DK_STORE` set per call. The installed `C:\Users\puls\go\bin\dk.exe`
is **v0.4.0** and is refused by the version gate.

## Discrepancies and additions

| # | Analysis said | dk v0.5.0 does | Consequence |
|---|---|---|---|
| 1 | Exit codes 11-16 | Also **10** `not-found`, **2** `usage` (no store configured, bad flags), **17** `forbidden`, **18** `quota`, **19** `secret`, **1** other. | The table in `store/dk-process.ts` covers all of them. |
| 2 | Errors are exit codes plus text | With `--json` an error is **also** an envelope on **stdout** (`{"schema_version":1,"error":{"kind","exit_code","message"}}`) while the same text goes to stderr as `dricket: <message>`. | The decoder reads the envelope first, the exit-code table is the fallback. |
| 3 | Exit 14 "not allowed" | A release the actor's role may not make — `agent may not release t-2 from in-progress to done` — is **14 `invalid`**, not 17. So an **agent cannot release straight to `done`**; `done` is a human/other transition. A release of a ticket claimed by someone else is **11 `claimed`** ("claimed by X, not by you"), not 13/14. | E14-5 must release to `review` (or `blocked`) and leave `done` to the owner's accept; exit 13 is not reachable from the commands exercised and stays unit-tested only. |
| 4 | `ls --json` is a list | `{"data":{"tickets":[...]}}`, and `"tickets": null` when nothing matches. `labels` is a comma **string** and is omitted when empty. No `depends`, `claimed_at`, `lease_until`, `size`, `branch`, `repos` (confirms R-05). | The store maps `null` to `[]`; board-level fields wait for R-05. New R-22. |
| 5 | `show --json` returns the raw file | Confirmed: `{"data":{"id":"t-1","content":"<whole file>"}}` — flat front matter, **every key present** (`owner: ` with a trailing space when empty, `labels: `, `depends: `, `claimed_at: `, ...), then `## Description`, `## Result`, `## Log`. No parsed fields, no comments (R-06). | The flat reader trims values and treats empty as null. A title with a colon (`First: a title`) is valid and reads correctly. |
| 6 | `extend` takes optional text | `dk extend -m <reason> <id>` — the reason is **required** (exit 2 without). Returns `{id, epoch, extensions, max_extensions, lease_until}`. | `TicketStore.extend` requires a `reason`. |
| 7 | `claim --size S\|M\|L` | Confirmed; the lease is **2 h for S, 8 h for M** with the default `dricket.toml`. `claim` is **idempotent for the same owner** (exit 0, `takeover:false`, the lease unchanged). `--kind` defaults to `agent`; a human claim needs `--kind human`. | The port carries `kind`; the fleet always claims as `agent`. |
| 8 | Claim bumps the epoch | Confirmed: epoch 0 -> 1 on the first claim, **stage becomes `in-progress`** by itself, `rev` +1; release to `review` keeps `epoch: 1`, clears owner and lease, `rev` +1 again. The release message lands in `## Result` **and** in `## Log`. | Stage vocabulary is dricket's (`open`, `in-progress`, `review`, ...); Drey's phase ids need R-03. |
| 9 | Comments are listable later (R-08) | `dk comment` works and returns the file path (`tickets/t/0000/t-1/comments/<ts>-<owner>.md`); there is **no command that lists comments**, and `dk inbox` reports `new_comments: null` even right after a comment. | `TicketStore.comments()` on dricket throws `unsupported` naming R-08; **no workaround** (no reading the store branch with git). |
| 10 | `dk --version` | Three text lines: `version: v0.5.0`, `commit: none`, `date: unknown`. No `--json` form. | The gate parses `version:`. New R-23. |
| 11 | A store is found from the cwd | Also from `DK_STORE`; with neither: exit 2 `usage`, "no ticket store found". | The wrapper always sets `DK_STORE` (never relies on the cwd) and `DK_DATA_DIR`. |
| 12 | — | Every command prints a `project: t (prefixes.toml (single registered prefix))` line to **stderr**. | Harmless; stdout stays the pure envelope. |

## Not exercised live

Exit 12 (conflict) and 13 (claim lost) need two writers racing or an expired
lease with a shortened `dricket.toml`; lease expiry and takeover belong to E14-5
(the plan there already calls for a shortened lease on a scratch store). They
are covered by the exit-code table tests only. Exit 15-19 likewise. Remote
stores (`<remote>#<branch>`) were not tried — local store only (OD-8).
